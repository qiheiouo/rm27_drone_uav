# 冲突邻机失联保护

## 为什么需要

状态帧超时后必须从邻机表删除，否则碰撞预测会长期消费错误位置；但直接删除也意味着无人机可能在
不知道对方当前位置的情况下继续穿越冲突区域。确定性网络仿真已经观察到，链路中断会显著压缩两机
间距。因此 `SwarmLinkGuard` 在“及时删除过期状态”和“未知状态下继续飞行”之间增加一个有界、
可诊断的定点保持层。

保护默认关闭。只有启用集群避让并完成场地策略评审后，才应在实机配置中显式开启。

## 触发条件

保护不会因为任意邻机离开视野而触发。它只记忆碰撞预测报告中的最近危险邻机：

1. 发现冲突时进入 `MONITORING`，记录 `other_agent_id`；
2. 冲突消失但该邻机仍在接收视图中时，经过 `conflict_clear_confirm_s` 后回到 `CLEAR`；
3. 冲突尚未稳定解除、该邻机却因超时从视图消失时，进入 `HOLDING` 并锁定当前位置；
4. 邻机重新出现后进入 `RECOVERING`，继续保持位置；
5. 链路持续稳定达到 `recovery_confirm_s` 后，才回到普通冲突监控或清除状态；恢复确认期间再次
   掉线会回到 `HOLDING`，且不会移动原保持点。

邻机何时从视图删除仍由 `SwarmPeerRegistry.max_age_ms` 决定。保护状态机不建立第二套消息超时，
避免板级和核心对同一帧产生不同的新鲜度判断。

## 制导和安全优先级

保护激活时，运行时以捕获位置生成位置保持制导，并暂停活动航点轨迹，以便解除后从当前位置
重新规划。局部障碍避让仍可修正保持指令；普通集群让行速度偏置暂不执行，直到恢复确认完成。

保护只覆盖起飞、出航、搜索、目标接近和返航等常规运动状态。以下动作优先级更高，不会被阻塞：

- 撞击恢复和脱离；
- 估计器失效处置；
- 基座搜寻、精细归航与停靠；
- 紧急稳定和紧急降落。

保护激活时，`SafetyDecision` 进入 `SAFETY_DEGRADED` 并设置
`SAFETY_REASON_SWARM_LINK`，但不会自行请求返航或紧急降落。若链路长期不恢复，已有的任务硬截止
时间仍会触发紧急安全流程，且其制导优先级高于位置保持。

## 配置与诊断

```c
cfg.swarm_link_guard.enabled = 1u;
cfg.swarm_link_guard.conflict_clear_confirm_s = 0.30f;
cfg.swarm_link_guard.recovery_confirm_s = 0.30f;
```

运行时输出 `swarm_link_guard`，包含状态、危险邻机 ID、保持点、当前状态持续时间和链路是否恢复。
事件环记录：

- `swarm-link-hold`：进入失联保持，数值字段是触发时速度；
- `swarm-link-recovered`：链路通过恢复确认。

主机回归场景：

```powershell
.\build\swarm_sim.exe --scenario guarded-outage
```

该场景在两机都已预测到冲突时动态切断链路 1 秒，必须观察到双方邻机过期、位置保持、安全原因、
恢复确认、重新规划和最终冲突让行。当前确定性参数下最小间距约为 0.23 m；这只是软件回归结果，
不是实机安全距离。

## 已知边界

- 当前碰撞接口只报告最紧迫的一个邻机，因此保护也只记忆一个危险 ID；未来若碰撞接口输出多冲突
  集合，应同步扩展为固定容量危险集合。
- 保护无法判断无线静默、对方掉电和对方已经离开任务区域之间的物理区别，只采用保守保持动作。
- 实机仍需根据机体尺寸、制动距离、最大突发丢包时间和剩余电量确定超时与恢复确认参数。
