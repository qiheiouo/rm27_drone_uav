# 结构化遥测

## 用途

遥测用于回答“运行时当时认为发生了什么”：连续保存状态估计、任务状态、安全原因、输入健康、目标/基座相对位置、制导与控制输出。它与输入回放互补：遥测适合诊断，回放输入适合重现算法执行；遥测不包含原始图像、光流特征或完整传感器输入，不能直接交给 `nav_replay`。

## 帧格式 v1

每帧固定 152 字节。编码器逐字段写入小端序，不直接序列化 C 结构体，因此不受结构体填充和枚举宽度影响。浮点字段要求目标编译器使用 32 位 IEEE-754 `float`。

| 偏移 | 大小 | 内容 |
|---:|---:|---|
| 0 | 4 | 魔数 `RMNT` |
| 4 | 2 | schema 版本，当前为 1 |
| 6 | 2 | 帧长度，当前为 152 |
| 8 | 8 | 帧序号、单调毫秒时间戳 |
| 16 | 32 | 运行事件、安全原因、五类输入健康掩码和周期间隔 |
| 48 | 8 | 任务/估计器/安全/末端/恢复/目标/停靠状态 |
| 56 | 4 | armed、step-valid、watchdog、可见性等标志 |
| 60 | 88 | 位置、速度、偏航、质量、目标/基座相对位置、制导速度、加速度与偏航角速度指令、剩余任务时间 |
| 148 | 4 | 对前 148 字节计算的 CRC32（多项式 `0xEDB88320`） |

解码器拒绝错误魔数、未知版本、错误长度、CRC 不匹配、越界状态枚举和非有限浮点值。改变字段布局时必须提升 schema 版本，不能在版本 1 内静默复用字节。

安全原因在线上始终占 32 位；`SAFETY_REASON_SWARM_LINK` 使用 bit 8，因此加入失联保护不改变
v1 帧布局。旧接收端可以忽略未知高位，新接收端可据此区分普通碰撞风险与冲突邻机失联保持。

## 主机录制与检查

```powershell
.\build\mission_sim.exe --telemetry build\mission.bin
.\build\nav_telemetry_dump.exe build\mission.bin
.\build\nav_telemetry_dump.exe --csv build\mission.bin
```

`mission_sim` 每个有效或被运行时拒绝的周期写一帧。写入、编码或关闭失败会返回退出码 7。`nav_telemetry_dump` 逐帧检查格式、CRC 和帧序号；时间戳停顿或回退会计入 `time_anomalies`，但仍保留数据，因为这种异常本身可能正是待诊断故障。`--csv` 在校验同时输出便于绘图的文本，摘要写到标准错误，使重定向后的标准输出保持为纯 CSV。尾部不足一帧会被判为截断，而不是静默忽略。

主机以 100 Hz 记录时数据率约为 15.2 kB/s。构建目录内的测试文件属于本地产物，已由 `build*/` 忽略，不应提交到 Git。

## STM32 接入

`NavApp` 默认每 10 个导航周期生成一帧；导航频率为 100–200 Hz 时，对应 10–20 Hz、约 1.52–3.04 kB/s。编译时可覆盖：

```c
#define NAV_APP_TELEMETRY_PERIOD_STEPS 20u
```

板级 `nav_telemetry_write(frame, size)` 必须立即复制到低优先级固定容量队列并返回。不能在导航任务内阻塞等待外设，也不能在函数返回后继续引用传入指针，因为编码缓冲区位于任务栈。队列满时返回负值；发送序号仍会递增，接收端会把序号间隙计为丢帧。必需输入被运行时拒绝时，适配层会绕过降采样立即尝试发送一帧，以保留故障现场。

将 `NAV_APP_TELEMETRY_PERIOD_STEPS` 定义为 `0` 可从适配层完全关闭遥测。实物接入后必须测量编码耗时、任务栈峰值、队列容量和真实链路吞吐；当前频率只是软件默认值，不是硬件验证结论。
