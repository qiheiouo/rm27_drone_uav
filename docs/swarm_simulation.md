# 确定性多机网络仿真

## 目的与边界

`swarm_sim` 用于在没有实物时验证多机导航的软件闭环。每架虚拟无人机都运行独立的
`NavRuntime`、状态估计、任务状态机、轨迹规划、冲突检测和确定性让行逻辑；邻机状态不直接注入，
而是先编码为 48 字节 `RMSW` 状态帧，再经过主机侧网络队列，最终由接收端解码并写入
`SwarmPeerRegistry`。

它可以回答以下问题：

- 多个真实运行时能否通过当前线协议互相发现；
- 延迟、抖动、丢包、重复和乱序是否会被邻机表正确处理；
- 链路中断后邻机是否按本机接收时间过期，恢复后是否能重新加入；
- 冲突双方是否按 `agent_id` 给出一致的让行结果；
- 四机广播时固定容量队列和邻机表是否够用。

它不是射频、电磁干扰、时钟同步或真实飞行动力学认证工具。仿真中的最小间距只能作为软件回归
指标，不能代替实机安全距离、通信距离和失联策略验证。

## 每周期数据流

```text
到期网络帧
    -> RMSW 解码
    -> 邻机表去重/乱序/过期
    -> SwarmView
    -> 每机独立 NavRuntime
    -> 控制输出与动力学
    -> AgentState 编码
    -> 确定性广播网络
```

网络模型位于 `simulation/swarm_network.*`，只使用固定内存：最多 4 个节点、64 个在途帧，
单帧最多 48 字节。故障按每个发送节点自己的广播序号触发，避免固定发送顺序使某个 ID
永久承担全部丢包。相同配置和种子会得到相同结果。

## 回归场景

| 场景 | 网络条件 | 必须满足的结果 |
|---|---|---|
| `nominal` | 固定 20 ms 延迟 | 两机互见、双方发现冲突、仅高 ID 让行、无紧急状态 |
| `lossy` | 40–100 ms 延迟；每 4 帧丢 1 帧；每 5 帧重复；每 3 帧额外延迟 160 ms | 接收端实际记录重复与乱序，仍能发现冲突并确定性让行 |
| `outage` | 1.6–2.5 s 全链路中断 | 中断前互见，中断中邻机过期，恢复后重新加入并恢复冲突处理 |
| `guarded-outage` | 双方发现冲突后动态中断 1 s | 双方进入位置保持和安全降级，稳定恢复后重新规划并继续确定性让行 |
| `four-agent` | 四机、固定 20 ms 延迟、平行航线 | 每机同时持有其余 3 个邻机，无队列溢出或邻机表容量丢弃 |

两机交叉场景中，正常和有损链路要求真实轨迹间距大于 0.18 m。全链路中断场景只检查没有发生
几何接触（当前回归下限 0.10 m）；这是有意保留的降级指标。当前参数下，中断场景的间距明显小于
正常链路，说明将来实机必须根据测得的最坏通信中断时间配置更保守的速度、间距或失联动作。

## 运行方法

```powershell
.\build\swarm_sim.exe --list-scenarios
.\build\swarm_sim.exe --scenario nominal
.\build\swarm_sim.exe --scenario lossy
.\build\swarm_sim.exe --scenario outage
.\build\swarm_sim.exe --scenario guarded-outage
.\build\swarm_sim.exe --scenario four-agent
ctest --test-dir build -R "test_swarm_network|swarm_" --output-on-failure
```

程序只有在声明的协议、网络、邻机生命周期和运行时行为全部出现后才输出
`SWARM_SIM_SUCCESS`。网络队列溢出、非有限控制量、运行时拒绝、错误让行或场景分支未执行都会
返回非零退出码。

## 有实物后的替换方式

先测量实际链路的端到端延迟分布、突发丢包长度、重复率、乱序率、最大可用距离和四机同时广播
时的信道占用，再用这些值扩展网络配置和回归场景。之后优先验证失联减速/悬停策略；只有状态帧
链路稳定并取得实测数据后，再决定是否把 `TrajectoryMessage` 固化为新的线上帧类型。
