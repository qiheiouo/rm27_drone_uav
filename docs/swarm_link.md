# 集群链路协议与邻机表

## 当前边界

这一层解决“邻机状态如何安全地从通信驱动进入导航核心”，不负责选举、编队、
任务分配或全局路径优化。协议与 UART、CAN、Wi-Fi、无线串口等具体介质解耦，
板级驱动只需非阻塞地收发完整帧。

当前 schema v1 只定义 `AgentState` 状态帧。未来轨迹仍是算法内部的
`TrajectoryMessage`，尚未上链路；在运行时真正消费邻机未来轨迹之前，不提前固化
它的网络格式。

## 状态帧 v1

每帧固定 48 字节，逐字段小端编码，不直接发送 C 结构体，因此不受结构体填充、
编译器 ABI 或枚举宽度影响。目标编译器必须使用 32 位 IEEE-754 `float`。

| 偏移 | 大小 | 内容 |
|---:|---:|---|
| 0 | 4 | 魔数 `RMSW` |
| 4 | 1 | schema 版本，当前为 1 |
| 5 | 1 | 帧类型，1 表示邻机状态 |
| 6 | 2 | 帧长度，当前为 48 |
| 8 | 1 | `agent_id` |
| 9 | 1 | 标志，当前仅 bit 0=`valid` |
| 10 | 2 | 发送序号 |
| 12 | 4 | 发送端单调毫秒时间戳 |
| 16 | 12 | 位置 x/y/z，米 |
| 28 | 12 | 速度 x/y/z，米每秒 |
| 40 | 4 | 状态质量，范围 0–1 |
| 44 | 4 | 前 44 字节的 CRC32，算法多项式 `0xEDB88320` |

解码器拒绝错误长度、魔数、版本、类型、保留标志、CRC、非有限向量和越界质量。
CRC 只检查传输损坏，不提供身份认证或抗恶意篡改能力。

## 邻机生命周期

`SwarmPeerRegistry` 最多保存 4 个邻机，全部使用固定内存：

- 拒绝本机 ID，避免回环广播进入碰撞检测；
- 按 16 位序号拒绝重复和倒序，并正确处理 `65535 → 0` 回绕；
- 使用本机接收时刻计算消息年龄，不假设多机时钟已经同步；
- 超时条目释放槽位；满表且没有过期条目时确定性地拒绝新 ID；
- 统计接受、重复、倒序、回环、无效、满表丢弃和超时数量。

发送端时间戳保留用于日志和以后时钟同步，但不能直接作为当前消息年龄。所有无人机
必须在任务开始前配置唯一 `agent_id`，并使用相同导航坐标系和 SI 单位。

## STM32 适配

板级实现以下非阻塞接口：

```c
int nav_swarm_frame_read(uint8_t *frame, uint16_t capacity, uint16_t *size);
int nav_swarm_frame_write(const uint8_t *frame, uint16_t size);
```

读取接口每次返回一个完整帧；没有帧时立即返回负值。写入接口必须在返回前复制或
入队完整帧，队列满时立即返回负值，不能等待物理链路。

`NavApp` 每个导航周期最多处理 `NAV_APP_SWARM_RX_BUDGET` 帧，默认 4，避免通信
洪泛占满导航周期。它默认每 `NAV_APP_SWARM_TX_PERIOD_STEPS` 个周期广播一次，默认
为 5；导航频率为 100–200 Hz 时对应 20–40 Hz、约 0.96–1.92 kB/s。两个宏均可在
板级编译时覆盖；将发送周期定义为 0 可关闭广播。只有配置为 `SWARM_ENABLED` 时
`NavApp` 才会调用板级集群收发接口，默认的 `SWARM_DISABLED` 保持单机行为。

`NavApp.swarm_decode_errors` 和 `NavApp.swarm_tx_drops` 提供链路诊断计数，邻机表内
还有更细的接收统计。实机接入后仍需测量无线链路吞吐、端到端延迟、突发丢包、
干扰下的可用距离以及多机同时广播时的信道占用。

无实物阶段可使用[确定性多机网络仿真](swarm_simulation.md)，让多个独立 `NavRuntime`
通过本协议完成正常、有损、失联和四机容量回归；其中的故障参数只用于软件验证，不能替代实测链路指标。
